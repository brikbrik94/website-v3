# Legend v1.1-Felder: Client-Konsumierung (`legend_scale_id`/`legend_sections`/`icon`)

## Kontext

`geodata-plugin-standard` v1.1.0 (Issue [#1](https://github.com/brikbrik94/geodata-plugin-standard/issues/1))
und der zugehörige `geodata-updater`-Fix (Issues
[#96](https://github.com/brikbrik94/geodata-updater/issues/96)/[#97](https://github.com/brikbrik94/geodata-updater/issues/97),
live verifiziert 2026-08-12 19:27) liefern jetzt 6 neue Group-Felder plus einen Top-Level-Block
in `tiles.oe5ith.at/layers.json`: `width`, `dasharray`, `outline_color`, `outline_width`, `icon`,
`legend_scale_id`, `legend_sections`. Details: `geodata-plugin-standard/GEODATA_PLUGIN_STANDARD.md`
§5.

**Scope-Split:** `width`/`dasharray`/`outline_color`/`outline_width` benötigen neue Swatch-
Varianten (gestrichelte Linie, Linie-mit-Umrandung/Casing, Fläche-mit-Rand), für die `oe5ith-ci`
aktuell keine CSS-Klassen hat — Inline-Styles dafür sind laut
`oe5ith-ci/docs/for-coding-agents.md` nicht zulässig, da es sich um neue visuelle Muster handelt,
keine zur Laufzeit berechneten Werte (Ausnahme dort nur für z.B. Pixel-Positionen aus Messungen).
Diese vier Felder werden separat per GitHub-Issue an `oe5ith-ci` angefragt und in einer späteren
Runde nachgezogen. **Dieser Spec deckt nur `legend_scale_id`/`legend_sections` (geteilte
Farbskalen) und `icon` (generischer Fallback-Marker) ab** — beides reine Client-Logik ohne neue
CSS-Anforderung.

## 1. `legendSchemaVersion.ts` (neu)

```ts
/** Vergleicht einen Schema-"version"-String (z.B. "1.1") numerisch gegen ein Minimum
 *  major.minor — nicht als String (geodata-plugin-standard §5.6). Fehlender/kaputter Wert
 *  gilt als vor-1.1 (Gate schlägt fehl) — ein Client darf neues Verhalten nur bei explizitem
 *  Versions-Signal annehmen. */
export function isLegendSchemaAtLeast(version: string | null | undefined, minMajor: number, minMinor: number): boolean {
  if (!version) return false;
  const [major, minor] = version.split('.').map(Number);
  if (!Number.isFinite(major) || !Number.isFinite(minor)) return false;
  return major > minMajor || (major === minMajor && minor >= minMinor);
}
```

## 3. `resolveLegendItemsForGroup()` (neu, in `resolveLegendSwatch.ts`)

Pure, testbare Auslagerung der Auflösungslogik (statt inline in `Sidebar.ts`'s
`buildToggleEvent`, die DOM/fetch-abhängig und damit ungetestet ist):

```ts
export interface ResolvedLegendItems {
  items: { label: string; color: string }[];
  groupKey: string;
}

export function resolveLegendItemsForGroup(
  metaGroup: Pick<LayerMetaGroup, 'legend_scale_id' | 'legend_items'>,
  overlayId: string,
  styleVersion: string | null | undefined,
  legendSectionsById: Map<string, LegendSection>
): ResolvedLegendItems | null {
  if (metaGroup.legend_scale_id && isLegendSchemaAtLeast(styleVersion, 1, 1)) {
    const section = legendSectionsById.get(metaGroup.legend_scale_id);
    if (section) {
      return { items: section.items, groupKey: `scale:${section.id}` };
    }
    console.warn('[resolveLegendItemsForGroup] legend_scale_id ohne passenden legend_sections-Eintrag:', metaGroup.legend_scale_id);
  } else if (metaGroup.legend_scale_id) {
    console.warn('[resolveLegendItemsForGroup] legend_scale_id gesetzt, aber version-Gate (>=1.1) nicht erfüllt:', styleVersion);
  }

  if (metaGroup.legend_items && metaGroup.legend_items.length > 0) {
    return { items: metaGroup.legend_items, groupKey: overlayId };
  }

  return null;
}
```

`Sidebar.ts`'s `buildToggleEvent` ruft das anstelle der bisherigen inline
`metaGroup.legend_items`-Prüfung auf. `LayerToggleEvent.legendItems` ist weiterhin
`{label, type: SwatchType, color}[] | null` (jedes Item braucht einen Swatch-Typ fürs
Rendering) — `resolveLegendItemsForGroup()` liefert bewusst nur `{label, color}[]` zurück (der
Typ hängt von `metaGroup.type`/`layerType` ab, nicht von der Item-Quelle), `buildToggleEvent`
mappt danach wie bisher:

```ts
const resolved = resolveLegendItemsForGroup(metaGroup, overlayId, styleEntry?.version, legendSectionsById);
if (resolved) {
  const itemType = swatchTypeForLayerType(metaGroup.type ?? layerType) ?? 'dot';
  legendItems = resolved.items.map(li => ({ ...li, type: itemType }));
  legendGroupKey = resolved.groupKey;
}
```

Bleibt `resolved` `null` (weder Skala noch klassische `legend_items` vorhanden), greift wie
bisher der `color`-Swatch-Zweig.

`initSidebar()` bekommt einen neuen Parameter `legendSections: LegendSection[] = []`, einmalig
zu einer `Map<string, LegendSection>` gebaut. `MapPage.ts` übergibt `layersMeta.legend_sections
?? []` (bisher wird nur `layersMeta.layers` durchgereicht — `legend_sections` liegt als
Geschwister-Feld auf oberster Ebene und wurde bisher nirgends verwendet). Für `version` pro
Style: `styleEntry = layersMeta.layers.find(l => l.id === overlayId)`, `styleEntry?.version`.

## 4. `MapPage.ts`: Ref-Count-Key generalisieren

Die beiden `legendItemsRefCount`-Zweige in `toggleLayer()` verwenden aktuell `event.overlayId`
als Schlüssel und Entry-Id-Präfix. Ändern zu `event.legendGroupKey ?? event.overlayId` bzw.
`` `${event.legendGroupKey}:legend-item:${idx}` ``. Der Rest der Ref-Zähl-Logik (0→1 rendert,
N→0 entfernt) bleibt unverändert.

## 5. Icon-Fallback

const GENERIC_ICON_SWATCH_CLASS = 'fa-solid fa-location-dot'; // wie CoordsPage/HealthModule

export function resolveSwatchFromLayersMetaColor(type: string | undefined, color: unknown): LegendSwatch | null {
  const swatchType = swatchTypeForLayerType(type ?? '');
  if (!swatchType) return null;
  const resolved: LegendSwatch = { type: swatchType, color: extractLiteralColor(color) };
  if (swatchType === 'icon') resolved.icon = GENERIC_ICON_SWATCH_CLASS;

## 6. `MapLegend.ts`-Bugfix

`addEntry()` prüft aktuell `entry.color === null` **vor** `entry.type === 'icon'` — ein
Icon-Eintrag mit `color: null` (laut Standard-Beispiel 5.7 der Normalfall, z.B.
`ski-lift-stations`) würde fälschlich den „❓ Farbe nicht auflösbar"-Fallback rendern statt das
Icon. Reihenfolge tauschen, `icon`-Zweig degradiert bei fehlender Farbe auf CSS-Default
(`var(--muted)`) statt hartcodierter Farbe:

```ts
} else if (entry.type === 'icon') {
  const marker = document.createElement('i');
  marker.className = `${entry.icon} ${typeClass}`;
  if (entry.color) marker.style.color = entry.color;
  div.appendChild(marker);
} else if (entry.color === null) {
  // bisheriger Fallback, jetzt nur noch für dot/line/area
  ...
}
```
